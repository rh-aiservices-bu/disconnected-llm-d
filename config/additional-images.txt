# Images llm-d needs that are NOT already in the CRIAB mirror.
#
# This file is the source; scripts/10-stage-images.sh appends these lines into
# CRIAB's config/additional-images.txt, which is what oc-mirror actually reads.
# Kept here as well so this repo records its own requirements — a rebuilt
# environment can reconstruct the list without reading a script.
#
# It is short by design. Everything else llm-d runs arrives through content
# CRIAB already mirrors:
#
#   vLLM serving image         RHOAI operator bundle relatedImages
#   endpoint picker/scheduler  RHOAI operator bundle relatedImages
#   storage initializer        RHOAI operator bundle relatedImages
#   Istio proxy / gateway      servicemeshoperator3 bundle (INSTALL_SERVICE_MESH3)
#
# scripts/20-verify-mirror.sh checks that claim against the running cluster
# rather than trusting it.
#
# Digest-pinned. A tag that moves between mirror time and deploy time produces a
# pull error naming an image you are certain you mirrored, which is a genuinely
# hard failure to reason about on a disconnected cluster.
#
# Re-pin with: scripts/10-stage-images.sh --resolve

# scripts/14-gpu-driver-disconnected.sh diagnose says the CUDA fetch is failing
# — but mirror it in the same batch as the models, because discovering you need
